# Juicy Tilt 设计与实现

## 产品目标

Juicy Tilt 是 MicroPixel 的第三款完整 Guest 游戏。玩家通过倾斜设备控制滚球，在不持续触摸屏幕的
情况下穿过迷宫、收集三颗星并进入终点。第一版面向 480×480 ESP-Mosaico 和 720×720
Metalio-Claw4，同时保留其他方形显示 profile 的自适应降级路径。

## 坐标与双分辨率素材

游戏逻辑和 Scene 始终使用 720×720 坐标。物理 480×480 profile 的比例为 2/3。

| 内容 | 720 profile | 480 profile |
|---|---:|---:|
| 棋盘底板 / 外围边框 | 600×600 | 400×400 |
| board tile atlas frame | 96×96 | 64×64 |
| board tile atlas（5×2） | 480×192 | 320×128 |
| object atlas frame | 96×96 | 64×64 |
| object atlas | 384×384 | 256×256 |
| 标题贴图 | 240×60 | 160×40 |
| HUD icon frame | 60×60 | 40×40 |
| HUD icon atlas | 180×60 | 120×40 |
| fan atlas（8 帧） | 768×96 | 512×64 |
| mechanic atlas（4×2） | 384×192 | 256×128 |

`Resources::LoadNativeTexture()` 保留选中变体的原生像素尺寸。Scene destination 仍使用逻辑坐标，因此
480 资源的 400×400 source 显示到 600×600 logical destination 后正好是 400×400 物理像素。未知
profile 使用 720 资源和普通 `LoadTexture()` 自适应加载。

素材不从概念预览图直接切取。ImageGen 负责标题、星星和冰面等美术母图；母图不包含关卡
几何、碰撞边界或整块 HUD。`assets/source/levels.json` 是墙体、起点、终点和障碍的唯一几何源，
`generate_gameplay_assets.py` 用母图填充精确 tile mask，并同时生成两套通用棋盘底板、外围边框、
board tile atlas、object atlas、标题、HUD atlas、启动图和 `tilt_level_data.hpp`。board atlas 包含
无方向 2D 墙块、冰面和八方向气流；生成器从关卡
数据输出精确连接拓扑，L02–L100 的接头吸附到 78px 的 7×7 迷宫节点；共线碰撞矩形先合并，显示墙段再在
18×18 节点方块边缘分段。这样可保证 480/720 输出、alpha、atlas frame 和碰撞对齐可复现。最终 PNG、母图和
生成头文件纳入版本控制，production Bundle 构建不运行素材制作脚本。移动挡板、状态门、压力板和
传送盘也使用 ImageGen 母图；生成器负责方向变体、开关状态、配对颜色和 atlas 装配。
每段显示墙在运行时均匀拆成不超过 20×18 的近方形小块，节点本身保持 18×18。墙块只使用统一底色、
窄幅四边分隔线和四向对称的中心菱形纹理，不使用材质纹理、渐变、方向光、高光、阴影、倒角或投影，
因此旋转方向和连接顺序不会改变外观。
board atlas 只保留 10 个实际使用帧，不复制墙块或接头帧；720 profile 的 RGBA 解码体积由约 1.18 MiB
降至约 0.35 MiB，避免在底板和透明外围框已经常驻后耗尽纹理分配空间。

## Scene 拆分

```text
Scene
├─ game_container
│  ├─ board_base_sprite
│  ├─ board_tile_batch      # 冰面、两处气流、最多 172 个墙块（含推导接头）
│  ├─ board_frame_sprite    # 覆盖拼接端点的连续外围边框
│  ├─ object_batch          # 三颗星、坑洞、弹簧
│  ├─ fan_batch             # 外壳固定、八帧内叶轮
│  ├─ blocker / timed gate / pressure gate sprites
│  ├─ pressure plate / portal sprites
│  ├─ goal_sprite
│  ├─ trail_batch
│  ├─ marble_sprite
│  └─ particle_batch
├─ hud_container
│  ├─ title_sprite / level / time
│  ├─ three-star atlas batch
│  └─ tilt_icon             # 贴图式倾斜指示器，不依赖 rotation
└─ modal_container
   ├─ dim overlay
   ├─ state labels
   └─ level selector / START / RUN FROM 01 / pause actions
```

棋盘底板和外围边框是通用贴图；墙、冰面与气流从透明 atlas 在关卡切换时拼装。物理直接读取
`LevelData.walls`；显示读取生成器由这些矩形确定性推导的 `visual_walls/wall_joints`，不维护手写视觉
tile map，因此碰撞与画面保持同源，同时避免原始矩形在节点处重复绘制。动态物体共享透明 atlas。
品牌标题和图标使用分辨率对应贴图，动态关卡号和时间仍使用 Host 语义字体。正常帧只 patch 球、倾斜
指示器、轨迹、粒子和必要的 atlas source，不更新静态 board tile；切换关卡时一次性改写 163 个固定槽位。

## 界面与流程

- 开始页不重复绘制品牌标题，也不在棋盘中央解释基础目标；左右按钮只在对应方向仍有已解锁关卡时
  显示（第一关隐藏左箭头，当前最高已解锁关隐藏右箭头），`START` 从所选关卡开始，`RUN FROM 01`
  从第一关连续推进，直到失败、退出或完成第一百关；
- 重玩较早关卡不会回退最高已解锁关卡，也不会清空最佳时间和评级；
- 游戏中点击左上角品牌贴图进入暂停。暂停时物理、计时、风扇动画和全部机关周期冻结；`RESUME` 先重新
  校准中立位再继续当前状态，`RESTART` 重新开始本关；
- 开始页唯一的辅助提示位于棋盘底部，用于说明品牌贴图也是暂停入口。

## 玩法模型

- 迷宫区域：逻辑坐标 `(60, 96, 600, 600)`；
- 纹理图集的透明留白可能跨出迷宫区域；所有可见 Sprite/粒子提交前必须限制或裁剪到
  `720×720` 逻辑画布内，满足 Host retained-scene 的矩形校验；
- 球使用圆形模型，墙使用圆角视觉、轴对齐矩形碰撞；
- 加速度投影经过中立位校准、低通滤波、死区和幅度限制；
- 物理按最多四个固定子步推进，限制最大速度，避免穿墙；
- 冰面按球体与贴图矩形的实际相交范围生效，而不只检测球心；首次接触时沿入射方向把速度提高 18%，
  接触期间保留绝大部分动量，并把倾斜修正能力降为普通地面的 60%，让一个格子的冰面也能产生明确
  但可预判的加速滑行动作；
- 所有关卡都必须收集三颗星后终点才解锁；掉入坑洞回到本关起点；弹簧反射并增加速度；
- 坑洞只用于第一关的开放式教学版面；L02–L100 的格子迷宫不放坑洞，避免它把唯一入口压缩成理论可达但真人
  无法稳定通过的窄缝；
- 切换关卡时视觉终点与模型终点必须同步更新；进入已解锁终点即通关，终点光环绘制在球上层；
- 墙壁音效只响应法向速度超过阈值的真实撞击，持续贴墙的接触修正不触发音效；
- 所有风扇都是周期阵风，不保留可被轻易抵消的持续弱风；停机时叶轮静止并降低亮度，喷发时高速旋转，
  标记范围边缘的推力也超过玩家最大反向倾斜加速度，玩家必须观察熄灭窗口通过，不能硬顶；
- 移动弹簧按确定性的往返周期运动，位置与碰撞共享同一模型；
- 移动挡板的往返位置和定时门开窗由 elapsed time 确定；压力板首次触发后锁存开门，视觉与碰撞共享状态；
- 紫色传送漩涡是单向陷阱，误入后保留 72% 入射速度并被送回青色圆盘；青色圆盘本身不触发传送，
  球必须先离开出口范围，入口才会重新武装；
- 通关评价分为 1/3 三星通关但有掉落、2/3 三星且零掉落、3/3 三星、零掉落且达到关卡 par time；
  最佳时间与最高评级分别写入 App 私有 KV；
- 音效参数只维护在 `audio/sfx.json`。

## 难度与关卡扩展

游戏不通过缩小棋盘来堆难度，而是在同一 600×600 逻辑区域提高路线密度和动态组合。L1 是唯一的
开放式教学关，包含滚球、墙、星星、坑洞、冰面，以及沿墙以 3000 ms 周期短距离往返的弹簧。

L02–L100 使用确定性候选 seed 流驱动的 7×7 深度优先迷宫生成器。球直径保持 36；难度来自路线转折、
折返和时序，不缩小游戏区域或物品。L02–L07 形成教学坡度：

1. L02：单脉冲风扇；
2. L03：相位错开的双脉冲风扇；
3. L04：加入会完整让出通路的移动挡板；
4. L05：加入定时门；
5. L06：加入锁存压力板和状态门，必须先完成明确折返；
6. L07：加入紫色陷阱漩涡和青色返回点，误入会被送回已经走过的区域。

L08–L100 组织为十章闯关曲线。每章包含路线记忆、移动风场、定时链、传送选择、交叉风场等不同题型；
第五关是短暂的喘息关，第十关是综合考试。非传送迷宫的额外回路从前期 3 条逐章减少到后期 0 条，
压力开关最低折返从 4 步提高到 10 步，传送失败的最低回退距离也逐章提高。章节目标用时和静态难度分数
同时上升，避免 L20 与 L100 只是换皮同级题。

压力板保持低矮且只占单格中心，熄灭/点亮状态直接对应门的关闭/打开。生成器禁止把压力板放在自然
三星路线上，并要求相对通往门口的最短路线按章节至少增加 4～10 步折返。紫色传送陷阱只放在棋盘内部四格的
最短三星路线格内，并与其他动态机关至少隔开一格；入口封住直路，但移除该格后必须存在至少四步的
完整格子旁路。玩家通过观察迷宫改走旁路，误入则至少倒退四格，不依赖像素级贴边操作。
入口与返回点画面距离至少约三格，且不能占用星星、压力板等必要检查点。传送盘只在自身轮廓内发光，
不绘制覆盖棋盘的范围特效。生成器在
`(cell, stars_mask, pressure_gate_open)` 状态空间中执行 BFS；只有收齐三颗星并抵达终点、且不触发
陷阱的安全状态路线才会写入关卡数据。陷阱行为另行验证为单向回退，不能成为反向捷径。

所有传送关都使用更严格的可操作性门禁：所有通道开口为 70 逻辑像素，直径 36 的球拥有 34
像素总横向余量；旁路的完整中心线不得进入任何风扇作用半径。几何上只有几个像素可走、或者需要在
风场里贴墙绕过传送入口的候选直接拒绝。

相同外观的机关使用固定物理常量，不随关卡编号暗中增强。所有脉冲风扇固定为 1100 推力、20 速度的
入风区阵风冲击、3000 ms 周期、1400 ms 吹风和 1600 ms 停吹；第二台风扇只改变相位。移动弹簧和移动挡板统一为 3000 ms
周期；定时门统一为 3600 ms 周期、1800 ms 开放。关卡难度只来自位置、方向、相位组合和路线拓扑。

技巧关从 L8 开始，L10 是第一次技巧考试；之后每章第六关再次出现并逐步收窄，让玩家在前十关内就能
体验操作上限。最终章在 L93、L96、L99、L100 设置四个 Inferno 技巧关。它们不暗中增强机关参数，
而是把同款脉冲风扇放在必经定时门的入口格，并把通道收窄到 54 像素：直径 36 的球只有 18 像素总横向余量。
玩家需要在风扇停吹且门打开的重叠窗口内控制速度和入射角；顶着风硬推无法通过，过早加速会撞门，
偏离中心线则会卡住窄口。生成器只接受该组合位于不可轻易绕开的关键边、并能通过三种相位扰动的候选。

生成器对起点、终点和三颗星执行带球半径的像素网格可达性检查，并计算最短全星路线、
转折数、通道净余量、机关恢复窗口和简化滚动时间。它还分别移除机关所在格或边，计算全星路线增加
的步数；没有形成至少两步绕路、也不是不可避开的机关不算有效难点。三颗星、终点在实际通路上至少相隔四步，画面上
至少间隔两格，避免多个目标挤在终点旁被一次经过顺手收完。每个风扇、冰面、移动弹簧、挡板、门、
压力板和传送返回点必须与三星路线相交；传送入口必须命中最短直路，自动通关路线则必须以完整格子
旁路避开入口。低挑战、无恢复窗口、
挡板退让不足或 par time 不合理的候选也会被拒绝。每关默认从 20 个静态合格候选中选择，seed、推荐路线、
机关关键度、物理测试结果和筛选指标一并保存到 `levels.json`，
因此同一输入可复现完全相同的关卡。

最终 par time 不再由静态代理公式决定，而是取三个物理试玩场景中最慢通关时间的 120%。通关本身不设
倒计时；这个目标允许先慢速理解按钮与门的关系，但精通要求减少等待、果断制动并沿状态空间最短全星
路线完成。

代理指标不能证明动态关卡可通。`tilt_autoplay_test.cpp` 以推荐路线驱动真实 `TiltModel`，逐帧输出倾斜
输入，并实际经过生产墙体、风场、挡板、压力门和传送门。候选必须在三种动态相位偏移、输入偏置、
确定性控制噪声和响应倍率下都收齐三颗星、零掉落通关才可入选。周期阵风在开启期必须压过玩家最大反向输入，并保留至少 600 ms 的停歇窗口。
移动挡板安装在格子边界并完整退让出开口，避免“图上连通、
物理上堵死”。

同一管线也可用 `--generated-count N --output ...` 输出独立目录。正式目录使用逐章抬升、章内波动的
难度曲线；筛选会对整个已选目录计算最近拓扑相似度，并拒绝旋转/镜像后
重复的迷宫以及完全相同的机关布局。关卡池按固定数量分批生成，物理候选也按固定数量分批编译，因此
内存和单次编译规模不随总关数线性膨胀。正式 App 已包含 100 关；关卡号使用三位显示，解锁状态、
100 份最佳时间和评级打包在一个带版本号的原子进度值中，并可从旧十三关独立 key 自动迁移。

## 传感器边界

Guest 通过 `Devices::List(DeviceKind::kSensor)` 找到加速度计，以 10 ms 请求间隔读取 Host 缓存快照。
核心玩法不依赖陀螺仪或磁力计。刚打开、改频率或 Resume 后的 `WouldBlock` 保留最近输入，不阻塞事件循环。

长期产品语义应由 Platform 把芯片原始轴统一为屏幕坐标（+X 向右、+Y 向下）。S31 真机已确认原始 X
与屏幕 X 反向、Y 同向，因此当前游戏输入映射翻转 X。P4 仍需真机确认；如果不同板型方向不一致，后续应
在 Sensor ABI 增加安装朝向元数据或在 Platform 统一为显示坐标。

## 容量预算

单关运行时加载 8 个只读 texture、7 个 SpriteBatch、213 个以内的 batch instance 和少于 40 个独立
drawable node，低于 256 个 node/instance、8 个 SpriteBatch 和 24 KiB Scene wire 上限。board batch
固定预留 1 个冰面、2 个气流和 172 个墙块槽位；当前最密关卡使用 168 个墙块。两套 profile
素材都在 Bundle
中，但运行时只解码匹配 profile 的一套。Bundle 由约 3.0 MiB 降至约 1.0 MiB。

## 验收

1. 原生 ASan/UBSan model test 覆盖墙碰撞、星星、坑洞、终点、评级、脉冲风扇、移动挡板、定时门、
   压力门和传送门；
2. 生产物理自动玩家从起点实际跑通 L02–L100 的全三星路线，任何关卡超时、漏星或精通路线
   掉落都会失败；
3. 资源生成器输出尺寸、alpha 和 atlas frame 数必须稳定，逐像素确认不存在大部分区域不可见的碰撞墙，
   并拒绝超过 160 段碰撞墙、64 个推导接头、172 个显示墙块或 2 个风扇的关卡；
4. `python3 tools/micropixel package guest/apps/tilt --aot-target riscv32-ilp32f` 通过；
5. 480 和 720 真机分别确认 source/destination 为 1:1 物理绘制；
6. 平放时无明显漂移，约 8～12° 倾斜可覆盖完整控制范围；
7. 稳定帧不更新底板、外围边框或 board tile batch，保持 60 FPS；
8. 真机确认 P4/S31 轴方向、音量、震动可用性和长时间游玩舒适度。
